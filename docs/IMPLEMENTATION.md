## 实际架构

- Electron 44.4.3 + React 19.1.1 + TypeScript 5.9.2；PDF.js 6.3.289 的原页 canvas 和公开 TextLayer。PDF worker、CMap、字体、WASM 全部本地打包。
- Electron 自带 Node 的 SQLite（WAL、FTS5），迁移版本 2。最初验证了 sql.js，随后改为内置 SQLite：避免每次更新重新写整库，支持 FTS5，无需本地 C++ 编译。中文字符分词加精确子串补查；尚非语义检索。
- Python 标准库 OOXML sidecar 用于 Office 重排。Docling 未安装，当前已有轻量适配器可以完成基础 Office 阅读，未将此称为 Docling 支持；复杂结构仍是限制。
- RapidOCR ONNX 1.2.3 + ONNX Runtime 1.30.0 + PDFium 5.11.0 提供无文字 PDF 单页本地 OCR。PyInstaller 包含 Python 和三份中英文 OCR 模型，发布包不要求用户安装 Python。
- 界面只使用预加载的有类型业务 IPC；sandbox、contextIsolation 开启，nodeIntegration 关闭，禁止任意导航和弹窗。Key 由主进程从用户选择的文本文件导入，使用 Windows safeStorage 加密；renderer 仅得到是否存在。文档、模型内容不执行 HTML，远程图片不加载。

## 生成与缓存的实际行为

简单问题：一次生成；程序校验失败最多一次修复。复杂问题：诊断、生成、审查，将结构与重大语义问题合并后最多一次修订，总调用上限4。经过语义修订但未复审的结果标 limited，不进入自动缓存。模型内容不作为独立事实证据。诊断和审查受运行时 schema 限制，任务输入不混入其他任务的输出schema。

缓存签名包含请求、根语境、读者配置、实际本地来源、模型和模板哈希；父版本不可变。精确命中先于Key检查和联网执行，离线仍能读缓存。网络研究缓存限24小时；检索策略变化和源片段变化导致签名变化。纠错标记递归隔离子节点。修订产生新文档ID，原始字节仍保留。尚未实现“只改无关页仍复用成品解释”的跨版本依赖匹配。

预算是保守token累计上限，不是供应商金额硬上限：请求前按UTF-8字节数加最大输出预留，usage返回后结算；无usage继续保留预留并标费用unknown。简单最多2次、复杂最多4次。无自动HTTP重试，避免超时重复计费。预生成仍执行同一预算路径。本地OCR有60秒时间上限，不产生模型token。搜索自身服务费用未建模，显示未知。

恢复记录不会自动启用云处理，也不把外部解释直接作为合格缓存。导出含原文提取快照、解释、关系、来源和用量，不含Key和原始PDF/Office字节。完整文件备份请按 RUNNING.md 复制关闭后的数据目录。

## 关键检查结果

- TypeScript 检查和构建通过。
- `npm test`：契约、Unicode、single-flight、SQLite持久化、缓存语境隔离、注入字段拒绝、30案例覆盖和空输出/截断/401等工程检查。
- `npm run e2e`：真实 Electron 窗口；原创 MD/TXT/DOCX/PPTX/数字扫描混合PDF；无Key拒绝；mock模型第二次精确缓存0请求；三层递归关系；刷新恢复内容路径；真实CPU OCR；父纠错隔离后代。详细记录在 test-results/e2e.json。模型响应仅为文档提供的fixture，不是AI效果证据。
- 实际OCR将 `f(x)=|x|` 识别成 `f(x) = [xl`。此错误保留为已知风险，行分数不是正确率；必须核对原页后手工修订，不能宣称公式可靠识别。
- 已查看阅读页、PDF页和解释页截图；不能据此声称跨栏、复杂Office或所有PDF视觉正确。
- 实际发布目录应用在PATH只保留System32时通过Office解析及扫描页OCR，证据在 test-results/packaged.json；没有借用开发Python。仍未在干净机器运行。
- 用户授权的临时Key已用于真实DeepSeek测试，20次调用共83,792 tokens；真实桌面一次生成后再次点击精确命中缓存、请求数不增加。Key仅由隐藏终端输入到短生命周期进程内存，未写入源码或应用凭证文件；测试进程已退出，测试profile无明文Key。不能从本地删除用户已发送的对话消息。完整结果见 EVALUATION.md。
- 未完成真实SearXNG搜索。没有独立人工盲评或学习者试用；AI审阅记录不冒充人工评审。
