# 实施与验收

## 1. 开发顺序

阶段是验证顺序，不是削减需求。先得到能真实使用的闭环，再扩展格式与检索；最终交付必须逐项说明完成、受限和未验证范围。

| 阶段 | 可运行交付 | 通过条件 |
| --- | --- | --- |
| M0 内容基准与契约 | schema、版本化模板、至少 12 个有参考判据的测试案例、模型适配器最小调用脚本 | 案例覆盖真实学习缺口；无 Key 可跑录制/模拟测试，有 Key 可测真实输出 |
| M1 阅读与解释闭环 | Markdown/TXT/数字 PDF；选区、解释、出处、本地缓存、递归子解释 | 关闭重启可复原，缓存命中零模型请求，返回父级不丢位置，正文无 Key 也能读 |
| M2 格式与 OCR | 扫描/混合 PDF、DOCX/PPTX 重排阅读、原图、OCR 修订与锚点 | 不静默丢内容，不可靠定位可降级，CPU 普通设备能完成基础使用 |
| M3 前置补充与研究 | 分范围概览、疑难预生成、参考库检索、真实 SearchProvider、预算与来源核查 | 预生成可取消；深搜有真实正文和引用，断网或未配置能诚实降级 |
| M4 产品交付 | Windows 发布包、依赖/模型管理、导出、恢复、性能与内容回归报告 | 干净环境可安装运行，无需用户启动开发进程；核心学习任务达到发布门槛 |

M0 不需要先做精美界面，必须尽早确认提示词是否真的补上缺口。M1 以后保持每阶段可用，不进行一次性全系统重写。

不写死实施天数。每阶段给出实际检查结果、待解决风险和下一步，不用计划表冒充完成记录。

## 2. 内容评测集

起步至少 12 个不同案例，发布前扩至至少 30 个。数量只是覆盖下限，不是质量证据；按失败类型补例。材料使用原创、获授权或许可允许的来源，记录出处和使用条件。

每个案例保存：原文及上下文、读者背景、解释任务、必要条件、必须补的桥梁、可接受论证、常见错误、来源、可选变式题及判据。不存在唯一措辞标准答案。

建议初始案例：

1. 方差相加：独立、交叉项、有限二阶矩，以及独立不是必要条件。
2. 连续与可导：差商、左右极限和反例。
3. 算法复杂度：输入规模、最坏与平均、适用条件，不把所有 O(n log n) 都解释为同一算法。
4. 化学平衡：动态过程、宏观稳定、模型条件，避免“反应停止”。
5. 物理图表：坐标轴、单位、比例和测量误差；图上缺失数据不得补造。
6. 相关与因果：给出混杂或替代机制，不能从单个相关数据推断因果。
7. 历史因果陈述：来源、语境、多种解释及证据力度。
8. 哲学论证：区分论点、前提和有效性，不偷换概念。
9. 同名概念“域”：数学与软件语境分别释义。
10. OCR 公式少了负号：识别出会改变结论的不确定性，不自信续写。
11. 文档中的恶意指令：解释内容但不泄露 Key 或访问任意路径。
12. 错误的父解释：递归追问时修正错误，旧缓存不继续传播。

还应增加中文长句、跨页否定条件、读者已经掌握前置、不应联网的基础释义、来源冲突、仅扫描表格等案例。

## 3. 内容评分与发布门槛

每项 0–4 分，有人工说明：0 缺失/错误；1 严重不足；2 部分满足；3 可用；4 清楚且充分。维度包括正确与边界、语境贴合、前置可达、关键推理/证据、例子、回原文、任务迁移与阅读负担。

必要门槛：关键事实、条件和来源不能有已知严重错误；不能伪造引用或已完成核查；不能把识别不确定当成确定正文。任何一项关键错误不能被其他维度高分平均掉。

初始发布目标：人工评审案例中至少 90% 达到“可用”或以上，关键事实与来源错误为 0 个已知未修复案例。该门槛是有限测试集的发布政策，不代表产品在所有输入上有 90% 保证或零错误。

模型审查用于筛查，人工评审用于检查代表性内容；数学/代码/数字可执行核验。来源 ID 有效只证明“引用存在”，还要检查片段是否真的支持主张。

学习者试用独立记录：能否复述、找条件、完成变式、回到原文继续读。初始可招募 5–8 位不同背景读者做定性试用，记录真实卡点与认知负担；不能用这样的样本量宣传统计性学习提升。

使用盲评比较基础提示与本方案：同一模型、同一证据、同一题集，另记录额外调用成本。需要比较不同模型时保持任务公平，不能将供应商或版本名称当作质量结论。

## 4. 核心行为验收

| 场景 | 必须观察到的结果 |
| --- | --- |
| 无 Key 打开文件 | 能阅读和搜索已索引本地内容，AI 功能显示待配置；不显示假答案 |
| 同选区同版本同设置解释两次 | 第二次来自本地缓存；网络拦截器记录 0 个模型请求 |
| 同词跨学科出现 | 不命中错误语境的成品解释缓存 |
| OCR 更正负号 | 新解释使用新文本；旧解释过期；其子节点有依赖变更状态 |
| 原文只改无关页 | 当前解释仍可按依赖校验复用，但引用版本必须准确 |
| PDF 缩放、旋转、跨行跨页 | 高亮与原句正确对应；不唯一时诚实提示定位失败 |
| 中文、emoji 和组合字符选区 | 程序 offset 映射正确，不截断或错位 |
| 解释连续追问三层再返回 | 路径、各层滚动位置、选区与对应内容全部保留 |
| 父解释修订 | 旧子解释仍可追溯原父版本，不能悄悄挂到新文字 |
| 多次切换文件并取消请求 | 不串页、不把旧任务答案显示在新选区、不写入半成品成功缓存 |
| API 返回空/截断/非法 schema | 明确失败，至多一次受预算限制的修复，不当作正常答案 |
| 401、429、超时、断网 | 凭证错误不盲重试；可退避错误有限重试；未知费用不记成零 |
| 搜索未配置或抓取失败 | 标明未联网核实；不能伪造网页与来源片段 |
| 多栏/表格/扫描混合 PDF | 阅读顺序可检查，未可靠识别部分可回到原图 |
| DOCX/PPTX 部分元素无法显示 | 显示重排或不支持状态，原文件可打开，不宣称原貌保真 |
| 预生成到预算上限 | 停止新增付费请求，已缓存内容仍可读 |
| 文档或网页含执行指令 | 不执行、不读取秘密、不修改服务配置 |
| 导出与恢复 | 解释、版本、原文出处、套娃关系可恢复；不包含 Key |

## 5. 性能与费用测量

给定硬件、文档大小、冷/热启动、是否已安装 OCR 模型后再报告数据。禁止不说明环境地宣称“秒开任意 PDF”。

初始体验目标：界面点击可在约 100 ms 内反馈状态；缓存解释 p95 小于 300 ms；普通已解码页的可用显示目标约 2 s。它们是待测目标，大文件、扫描和模型下载单独报告。模型冷启动/网络生成的首字时间和总耗时分别记录，不设未经测量的保证。

费用分开统计首次解释、缓存命中、预生成、审查/修订、图像识别与联网。价格表有日期与来源；日志缺 usage 时明确 unknown。以请求计数和 token 验证节约，而非仅展示好看的百分比。

测量连续使用后的内存、数据库体积与缓存增长，确认退出/取消能终止 worker，并且重新打开不会把所有页面重新 OCR 一遍。

## 6. 自动化测试的重点

使用单元测试验证锚点转换、缓存依赖、去重、预算、schema 和来源解析；集成测试覆盖 parser、SQLite 迁移、API 错误与取消；端到端测试覆盖真实阅读和套娃流程。

对模型质量采用可重放评测，不用字符串全等断言强迫固定措辞。录制响应要标注来源和日期；mock 只能证明工程流程，不证明教学质量或真实联网能力。

发布测试至少包含一个干净 Windows 用户环境下的打包应用启动、一个真实 PDF、一个真实 DOCX、一个真实 PPTX 和一个扫描/混合文档。图表/Office 转换表现需要截图或人工检查，单纯抽到字符串不够。

## 7. 完成报告格式

列出可安装运行的交付物和启动方式；逐项列核心能力的完成情况；列执行过的测试、真实 API 调用范围、样本类型与环境；明确未验证的模型质量、格式与设备限制。

不能把编译通过当成学习效果通过，不能把设计样例当成模型实测，也不能把 mock 搜索当成联网深搜已完成。阻塞项要说明精确原因及已经完成的不依赖部分。
