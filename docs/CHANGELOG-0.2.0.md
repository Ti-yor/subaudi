# 0.2.0：界面重构、可用性修复与瘦身

## 界面

- 全新设计系统（`src/ui/style.css`，令牌驱动，明亮 / 护眼 / 夜间三套主题）。旧样式表约 1,200 行、同一选择器反复覆盖自身（`header`、`aside`、`.settings` 各定义两三次），现为单一来源。
- 布局：标题栏（资料名 · 搜索 · 阅读/卡片切换）→ 资料库侧栏（格式标签、页数、批注/解释列表）→ 阅读区 → “页边”解释栏（朱色页边线是全应用唯一的强调元素）→ 状态栏（后台任务、扫描页提示、本月用量）。
- 选区浮动工具条取代右键菜单：解释、提问、四色高亮、批注、复制。新增“提问”：读者写下具体疑问，传给提示词既有的 `explicit_question` 字段（此前提示词要求回答它，但程序从未传入）。
- `Ctrl+K` 命令面板兼全文搜索：走 SQLite 索引、大小写不敏感、命中高亮、可切换当前/全部资料。旧搜索在渲染进程里对全部书的全部段落做大小写敏感的 `includes`。
- 拖拽导入、多选导入；欢迎页；骨架屏加载态；可撤回的 Toast；统一的确认对话框与键盘可操作菜单（取代以 `<details>` 冒充菜单、靠全局点击监听关闭的做法）。
- 文字类资料：排版正文列、字号/字体/行宽可调、标题目录随滚动高亮、幻灯片分隔、已解释段落旁的朱点。
- PDF：图标化工具栏、目录书签抽屉、扫描页内联“识别文字”提示与“全部识别”、导出批注 PDF 等收进“…”菜单。
- 设置改为四栏：AI 服务（服务商预设、粘贴 Key、测试连接）、阅读、用量（月度账本表）、数据与备份。
- 卡片库：牌组到期/新卡计数、居中卡片、彩色评分键（1–4）、浏览分页、卡片随主题配色。

## 后端：让功能真正可用

| 原设计 | 问题 | 现在 |
| --- | --- | --- |
| token 预算是**终身累计**、上限 100 万、默认 6 万 | 用几十次解释就永久锁死，只能不断手动调高 | 按自然月统计，默认 200 万/月，0 为不限 |
| 预留量 = UTF-8 **字节数** | 中文 1 字 = 3 字节，预算消耗被高估约 3 倍 | 按字符类型估算，结算时以服务商返回用量为准 |
| Key 只能从“仅含 Key 的文本文件”导入 | 需要先建文件、再选文件、再删文件 | 直接粘贴；可“测试连接”；可移除 |
| 云端解释需要全局开关 + 每文档开关 + Key 三重确认 | 首次使用要点三处 | 保存 Key 即启用；单份资料可设为“仅本地” |
| OCR / 修正一页文字 = **复制整份 PDF**、生成新文档 ID | 300 页扫描书识别 300 次 = 300 份 PDF 副本，书架隐藏“旧版本” | 原地更新该页；相关解释自动标记待复核 |
| OCR 拒绝有原生文字的页 | 混合页（扫描 + 少量文字）无法识别 | 任何页可识别 |
| 每次 OCR 新开进程并重新加载模型，60 秒超时 | 慢，且大页超时 | 常驻进程复用引擎与文档，180 秒超时 |
| Office 解析每次新开进程，60 秒超时，解压上限 150 MB，图片上限 8 MB | 大讲义直接失败，大图被丢弃 | 常驻进程，10 分钟超时，2 GB / 24 MB |
| 导入上限 100 MB，单选，TXT 仅 UTF-8 | 大 PDF、GBK 文本无法打开 | 1 GB，多选与拖拽，GBK 自动回退 |
| 任意后台任务运行时禁止删除批注/解释 | PDF 在后台建索引时什么都删不掉 | 只有删资料需要等待 |
| `state()` 每次把所有书的全部文字通过 IPC 发给界面 | 任意操作后刷新都很重 | 只发元数据；按需 `doc(id)` 取正文 |
| 导读要求模型引用的段落全部在范围内，否则整体报错 | 模型多引一个块就失败 | 过滤越界引用，保留有效部分 |
| 移除资料后私有副本留在 `objects/` | 数据目录只增不减 | 同步删除副本（原文件不受影响） |
| 制卡用“文字索引页数 < pdf-lib 读出的页数”判断 PDF 未就绪 | 每次制卡都要用 pdf-lib 整本解析一遍 | 索引时记录页数，直接比较 |

三个 sidecar 的进程管理统一为 `src/core/worker.ts`（常驻、FIFO 应答、超时/取消即重启、始终排空 stderr），替代原 AnkiBridge 与两段复制粘贴的 spawn 代码。

## 为什么臃肿、如何瘦身

本轮删除的历史产物至少 **2.6 GB**（不含 node_modules）；真正的源码不到 0.5 MB。

1. **历史发布物**：`release/` 下 v0.1.0 单文件 EXE（187 MB）与 v0.1.3–v0.1.6 四个完整解包版（v0.1.5 1.26 GB、v0.1.6 0.74 GB 等）。仅保留 v0.1.7。
2. **PyInstaller 中间目录**：每次重打包换一个目录名（`build`、`build-anki-update`、`build-v017`、`ocr-build`、`ocr-build-small`、`anki/build`），旧的从不清理，约 90 MB。构建脚本现会自行清理。
3. **`test-results/`**：每次回归测试保留一整份 Electron 用户数据目录，约 290 MB。
4. **sidecar 夹带无用依赖**：卡片库内核从全局解释器扫入 numpy、Pillow、cryptography（约 50 MB，Anki 的 Python 层从不导入）；OCR 带 OpenCV 的 FFmpeg 视频模块（29 MB）与 AVIF 解码（7.5 MB）。构建脚本已排除，**需在 Windows 上重新构建 sidecar 才会生效**。
5. **安装包**：Electron 全部 50+ 种界面语言（约 40 MB）→ 仅留中/英；`extraResources` 夹带开发文档与 `.py/.pyc` 许可证副本 → 移除；渲染与主进程 JS 未压缩并内嵌 sourcemap（`main.cjs` 2.8 MB + 4.8 MB map）→ 生产构建压缩、不带 map（JS 合计 7.5 MB+12 MB map → 1.8 MB）；pdf.js 查看器样式表（180 KB，只用到其中文字层的 40 行）→ 内联；旧版提示词模板 → 只打包 manifest 引用的版本。
6. **一次性脚本**：Codex 为各版本写的 20 余个回归/修补脚本（`reader-v015.mjs`、`workspace-v017.mjs`、`fix.py` 等），针对旧 DOM，已无法运行 → 由一个 `scripts/ui-smoke.mjs` 取代。

## 验证

- `tsc --noEmit` 通过；单元测试 25 → 29 项全绿（新增常驻 worker 复用/超时/取消重启、token 估算、阅读器搜索）。
- `npm run ui`：真实 Electron 窗口走完 19 个步骤（导入 5 种格式 → 选区 → 提问 → 未配置引导 → 设置/测试连接 → 解释 → 依据 → 高亮 → 导读 → 搜索 → PDF → 菜单 → 幻灯片目录 → 三主题 → 卡片），零页面错误。
- 未在本轮验证：Windows 上的 sidecar 重新打包与便携 EXE 实机启动（构建环境为 Linux）。
