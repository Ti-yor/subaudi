# Subaudi 0.1.3

修复模型输出不是合法 JSON 时直接把 SyntaxError 抛给用户的问题。先在本地处理完整代码围栏、字符串外尾逗号；不推测缺失的正文、引号或转义。不明确的语法错误会在现有简单两次/复杂四次调用预算内请求至多一次格式修复。所有输出仍须通过原有结构和来源校验；重复失败不保存成功缓存。

PDF 底部新增“本地处理进度”，展开显示实际读取大小、文字检查页数、已提交缓存页数、本次复用页数、待 OCR 页数和已有 OCR 缓存。已保存计数仅在索引写入成功后更新。OCR 显示页码、运行时间、识别/保存/完成/失败事件；不提供虚假的识别百分比。

OCR 仍由用户按页触发。空白或扫描页的文字索引完成不代表 OCR 完成。相同文档版本和页码的 OCR 结果可持久复用；后台索引在 OCR 运行期间新增的页面不会因保存 OCR 修订而丢失。

验证：18 项单元测试；真实 Electron 请求体回归覆盖本地语法恢复、一次格式修复、持续失败和复杂调用预算；真实 PDF/OCR 进度测试覆盖落盘计数、待 OCR 提示、运行时间、保存事件、重复识别缓存以及重新打开后的缓存复用。故障模型响应为受控测试数据，本轮不以模拟测试冒充真实模型效果。

证据：`test-results/complex-regression.json`、`test-results/progress-regression.json`、`test-results/processing-ocr.png`、`test-results/processing-complete.png`。
